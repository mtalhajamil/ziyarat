# Ziyarat

A static, build-free website for exploring places of ziyarat. Read [AGENTS.md](AGENTS.md) for the repository's mobile-first, accessibility and content-separation guardrails. Do not invent historical descriptions, translations, locations, photo identities or licenses; use supplied or verified information and leave missing content marked as such.

## Run locally

From the repository root:

```sh
python3 -m http.server 8000
```

Open `http://localhost:8000/`, or visit `http://localhost:8000/madinah/quba/` directly. The browser needs JavaScript and an HTTP server to fetch the templates and JSON; opening files using `file://` does not work. There is no build step, framework, package installation or server-side application. Node.js is needed only for the tests below.

## How it works

| Path | Responsibility |
| --- | --- |
| `index.html`, `madinah.html`, `nearby/index.html`, `{madinah,makkah,badr}/index.html` | Static page shells, navigation, asset versions and content containers. |
| `data/destinations.json` | Ordered destination IDs for the homepage. |
| `data/{madinah,makkah,badr,taif,turkiye}.json` | Each destination's card metadata and, where available, ordered places and theme. |
| `{madinah,makkah,badr}/*/index.html` | Small compatibility redirects for old shared place links, generated by `scripts/generate-redirects.cjs`. |
| `templates.html` | Reusable destination and place markup, including missing-content states. |
| `site.js` | Fetches and validates the data and templates, renders the page, and handles place navigation. |
| `styles.css` | Shared responsive styles, destination themes and locally hosted Urdu font. |
| `assets/vendor/leaflet/` | Leaflet 1.9.4 map library, distributed under its included BSD-2-Clause license; source: https://github.com/Leaflet/Leaflet/tree/v1.9.4. |
| `assets/images/`, `assets/fonts/`, `assets/favicon.svg` | Local site assets. The Noto Naskh Arabic font license is `assets/fonts/OFL.txt`. |
| `tests/*.test.cjs` | Node tests for rendering, validation, routes, nearby map behavior and asset versions. |

The page shell loads `site.js`, which fetches `templates.html` and the relevant JSON with `cache: 'no-cache'`, clones a template and inserts text as text rather than HTML. Invalid data or failed requests produce an error message instead of partial content; inspect the browser console for details. All place entries for a destination are validated before a place is shown, so one invalid entry can prevent that destination's places from loading.

“Places near me” plots the 27 user-supplied Madinah coordinate pairs in `data/madinah.json`; these pin locations have not been independently verified. Masjid-e-tooba is excluded because its supplied coordinates point to Karachi; its existing page remains available. The page requests browser geolocation on entry and lists the five closest places by straight-line distance; visitors can instead select an origin by tapping the map or using its keyboard controls. The list links to descriptions using each place's unique `sourceCode` to associate its coordinates with its record; map pins open the supplied Google Maps place links. The trip button requests the device's current location separately, selects its five nearest places and opens Google Maps with the nearest remaining stop at each step; this is a straight-line approximation, not road optimization. [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started#directions-action) support at most three waypoints in mobile browsers, and some products ignore waypoints, so the complete five-stop route is not guaranteed on every client. The map's full-screen control uses native fullscreen when available and otherwise fills the viewport; use the exit control or Escape to return. Precise location is not stored or sent to this site; map tile requests reveal the approximate viewed area to OpenStreetMap, while opening a trip shares its origin and stops with Google. The map uses OpenStreetMap standard tiles with visible attribution and normal browser caching, without prefetching; see the [tile usage policy](https://operations.osmfoundation.org/policies/tiles/).

Place descriptions show English by default. The compact, right-aligned EN/UR box toggle switches between available descriptions, with Urdu rendered right-to-left; the selection resets to English when a place opens. If a translation is missing, its panel displays a translation-coming-soon message rather than invented history. Descriptions longer than three rendered lines start clamped and get an accessible Show more/Show less button; shorter text has no redundant button. Places with neither description show “Description coming soon” without language controls. Supplied YouTube links appear as external “Watch place video” buttons beside the map link, wrapping on narrow screens.

The homepage links to each available destination's directory index, which displays its first place. Taif and Turkiye still show “Coming soon”. A shareable `/<destination>/?place=<slug>` URL opens a specific place; existing `/<destination>/<slug>/` links redirect there. The legacy `madinah.html` still opens Madinah. The arrows update content in-page, support browser back/forward, and wrap around within that destination's JSON order; a subtle transition respects reduced-motion preferences. Both arrows are disabled when there is only one entry.

The page container's validated `data-destination` selects its JSON and navigation prefix; older Madinah shells omit it and default to Madinah. A further available destination needs a matching JSON file with theme and places and a destination page shell; adding a homepage link alone is not enough. Makkah and Badr currently use missing-image and missing-description placeholders, not inferred historical details.

Directory pages use a relative `<base>` so links, scripts, styles, data and images resolve under the GitHub Pages project path as well as at a local root. Keep the existing relative paths and test direct entry and refresh on nested pages; do not assume a server-side router or rewrite rules.

The homepage's Open Graph and Twitter Card metadata is in the initial `index.html`, so sharing services can read it without JavaScript. The canonical URL and share-image URLs are absolute and tied to the GitHub Pages address; update them if the site moves. `assets/images/share.jpg` is a 1200 × 630 JPEG. Social platforms may cache old previews after a deployment.

## Destination theme guide

The homepage has its own warm-neutral theme (`#f7f6f0` background, `#242d26` text). Place pages share a layout but use validated `theme` values from their destination JSON: Madinah is light green with deep-green controls, Makkah is warm ivory and charcoal, and Badr is soft red with deep-red controls. Video buttons use a contrasting accent. The destination selected by `data-destination` on the place content container also selects its JSON; legacy Madinah pages without the attribute default to Madinah. Theme values use six-digit hex colors or `rgba(r, g, b, a)`; `shadow` is an RGB triplet. See `styles.css` for layout and gradients.

The following are proposed starting palettes for destinations that are still coming soon; confirm the direction with the owner when implementing them:

| Destination | Background | Main text | Dark control | Direction |
| --- | --- | --- | --- | --- |
| Taif | `#faf3f1` | `#443436` | `#6c4046` | Soft rose and warm neutrals. |
| Turkiye | `#f2f6f7` | `#293e45` | `#305764` | Pale blue-gray and muted teal. |

Keep the existing light, calm visual language: centered place heading, proportionate local image, full-width map link, readable bilingual descriptions and compact breadcrumb. Use dark text on light surfaces and white text on dark controls; check the actual rendered colors, including translucent layers, for at least 4.5:1 normal-text contrast and visible focus. Preserve the existing system/Georgia typography and local Noto Naskh Arabic for Urdu unless a different design is requested. Apply the mobile, touch-target and accessibility requirements in `AGENTS.md`; never assume a proposed palette or a place-specific design already exists.

## Add or update content

1. Edit the appropriate JSON file, not the reusable markup or rendering logic. Destination entries require a name and image; `page` and `description` are optional. A live `page` must be a relative directory URL ending in `/` or a simple `.html` filename, as validated by `site.js`.
2. A destination place requires a unique lowercase, hyphen-separated `slug`, `name` and an HTTPS Google Maps `mapUrl`. An optional `nearbyMapUrl` supplies a different Google Maps place link for the nearby map; otherwise it uses `mapUrl`. The accepted hosts and paths are checked in `site.js`. Retain a supplied spreadsheet identifier as `sourceCode`; mapped places require a unique code, which does not replace the stable route slug. Omit `image` if no reliably identified, licensed image is available. `english` and `urdu` are independently optional; if one translation is absent, its language panel says it is coming soon. Omit both when no description is supplied; the page then shows “Description coming soon”. Optional `videoUrl` must be a secure YouTube watch, shorts, embed or short-link URL.
3. Preserve supplied Urdu text and punctuation; only format it when requested. Put paragraph breaks in JSON as `\n\n`; the stylesheet preserves them and the template sets Urdu to `lang="ur"` and `dir="rtl"`. Translate supplied text faithfully rather than inventing additional content. Long descriptions are initially clamped to three rendered lines.
4. New places are available at `/<destination>/?place=<slug>` without a new page. To also support the old clean URL pattern, run `node scripts/generate-redirects.cjs` and commit the generated redirect. This is optional maintenance, not a build step.
5. If adding a photograph, put it in `assets/images/` and set `image.src`, `alt`, `width` and `height` to its actual local path and dimensions. Image filenames may contain letters, digits, `_` and `-`; supported extensions are `jpg`, `jpeg`, `png` and `webp`. Verify the subject and reuse license; never substitute a photo of a different place.
6. Record the source, creator, license and modifications below. Where a place photo requires visible attribution, add `image.credit` with `description`, `sourceUrl`, `license` and `licenseUrl`, following the Jummah entry. Credit URLs must be HTTPS; the place template renders the source and license links. Destination cards do not currently render image credits, so do not use an image requiring visible attribution there without implementing that support.

## Validate and deploy

```sh
node --test tests/*.test.cjs
git diff --check
```

The tests exercise the JSON renderer with a simulated DOM, validation, navigation and route files; they are not rendered browser or visual tests. When intentionally adding places, update the expected place names and map searches in `tests/site.test.cjs`. For UI changes, also check 320px and 375px mobile widths and desktop, including Urdu, image alignment, links and keyboard focus, when browser access is permitted. Report explicitly if visual checks cannot be performed.

When changing `styles.css`, `site.js` or `assets/favicon.svg`, update that asset's `?v=` value in every HTML page that loads it. Compatibility redirects do not load these assets. JSON and templates are fetched with revalidation; HTML and static assets may still be cached.

GitHub Pages is configured to publish the repository's `main` branch from `/` at [mtalhajamil.github.io/ziyarat/](https://mtalhajamil.github.io/ziyarat/). Follow the owner's instructions and repository protections when publishing. With an authorized `gh` session, check the latest build with:

```sh
gh api repos/mtalhajamil/ziyarat/pages/builds/latest --jq '{status,commit}'
```

After the intended commit is built, check the live homepage, changed nested routes, data and assets. Allow for GitHub Pages cache propagation; a successful Git push alone does not establish that the updated site is live.

Urdu text uses a locally hosted Arabic subset of [Noto Naskh Arabic](https://fonts.google.com/noto/specimen/Noto+Naskh+Arabic) with system font fallbacks, not a font CDN.
